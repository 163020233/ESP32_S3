# ESP32-S3 + W5500 以太网通信验证程序实现需求

## 一、项目目标

请基于 **ESP32-S3 + W5500 + ESP-IDF** 实现一个完整的以太网通信验证程序。

开发环境：

- IDE：CLion
- Framework：ESP-IDF
- MCU：ESP32-S3
- Ethernet 芯片：W5500

本程序的目的不是简单验证 W5500 是否能读取 VERSIONR，而是要验证：

> **ESP32-S3 通过 W5500 建立稳定的 100M 以太网通信链路，并验证 TCP/UDP 双向通信、数据完整性、压力测试、长时间稳定性以及断网恢复能力，为后续 RTL8305、IP 高清相机、网络喊话器及其他网络设备集成提供可靠的网络通信基础。**

---

# 二、硬件连接

严格按照以下 GPIO 实现：

| W5500 信号 | ESP32-S3 GPIO | 功能 |
|---|---:|---|
| W55_RSTn | GPIO4 | W5500 硬件复位 |
| W55_INTN | GPIO5 | W5500 中断 |
| W55_MOSI | GPIO6 | SPI MOSI |
| W55_MISO | GPIO7 | SPI MISO |
| W55_SCLK | GPIO15 | SPI SCLK |
| W55_SCSN | GPIO16 | SPI CS |


SPI：

```text
MOSI = GPIO6
MISO = GPIO7
SCLK = GPIO15
CS   = GPIO16
```

复位：

```text
RST = GPIO4
```

中断：

```text
INT = GPIO5
```

第一阶段可以暂时不依赖 INT GPIO5，但最终程序需要保留中断接口。

# 四、W5500 初始化

优先使用 **ESP-IDF 官方 Ethernet/W5500 驱动和 lwIP**，不要重新实现完整 TCP/IP 协议栈。

初始化流程：

```text
GPIO 初始化
↓
W5500 RST 拉低
↓
延时
↓
W5500 RST 拉高
↓
等待 W5500 启动
↓
SPI Bus 初始化
↓
W5500 Ethernet MAC/PHY 初始化
↓
esp_netif 初始化
↓
注册 Ethernet/IP Event
↓
启动 Ethernet
```

SPI 参数首先使用稳定配置，初始测试不要追求最高 SPI 频率。

# 五、第一阶段：SPI / W5500 硬件验证

启动后首先验证 W5500 是否能够被 ESP32-S3 正常访问。

至少检查：

```text
W5500 VERSIONR
```

正常值：

```text
0x04
```

串口输出类似：

```text
[W5500] Reset...
[W5500] SPI Init...
[W5500] VERSIONR = 0x04
[W5500] SPI TEST PASS
```

同时可以读写部分 W5500 网络寄存器，验证 SPI 双向读写。

这一阶段的目的：

> 确认 ESP32-S3 ↔ SPI ↔ W5500 硬件通信正常。

# 九、第五阶段：UDP 测试

ESP32-S3 开 UDP Server：

```text
UDP PORT = 5001
```

实现：

```text
PC → ESP32
ESP32 → PC
```

UDP 测试不能只发送字符串。

需要定义专门的测试数据包。

建议：

```c
typedef struct {
    uint32_t magic;
    uint32_t sequence;
    uint32_t timestamp;
    uint16_t payload_len;
    uint8_t  payload[1024];
    uint16_t crc;
} udp_test_packet_t;
```

具体实现可以根据工程需要调整，但必须包含：

- Magic
- Sequence
- Payload Length
- Payload
- CRC/校验信息

# 十、第六阶段：UDP 数据完整性检测

ESP32 收到 UDP 数据后，需要检查：

### 1. Sequence

例如：

```text

2
3
4
5
```

如果：

```text
1
2
4
5
```

说明：

```text

```

统计：

```text
lost_packets++
```

### 2. Duplicate

例如：

```text
1
2
3
3
4
```

统计：

```text
duplicate_packets++
```

### 3. Out Of Order

例如：

```text
1
2
5
4
```

统计：

```text
out_of_order_packets++
```

### 4. CRC / 数据校验

检测 Payload 是否损坏。

统计：

```text
data_error_packets++
```

# 十九、非常重要的技术要求

请注意：

**不要把“UDP 测试没有丢包”理解成 W5500 可以保证 UDP 永不丢包。**

UDP 本身不提供可靠传输。

本验证程序只是通过：

```text
Sequence
+
CRC
+
Statistics
```

来**检测当前网络环境下是否发生丢包、乱序、重复和数据错误**。

如果后续正式业务中的控制指令要求可靠交付，可以采用：

```text
UDP + Sequence + ACK + Timeout + Retry
```

或者对于必须可靠、有序的数据直接使用：

```text
TCP
```

# 二十、实现原则

请按照以下原则实现：

1. 使用 **ESP-IDF 官方 W5500/Ethernet 驱动**
2. 使用 ESP-IDF 自带 lwIP
3. 使用 FreeRTOS Task 管理测试任务
4. W5500、Ethernet、TCP、UDP、压力测试模块分离
5. 不要把所有代码集中到 main.c
6. 所有 GPIO/IP/端口/测试参数集中配置
7. 所有网络测试必须有统计结果
8. UDP 必须支持 Sequence 和数据校验
9. 支持长时间运行
10. 支持 Ethernet Link Down/Up
11. 支持断网恢复
12. 第一阶段先直连 PC
13. 第二阶段再接 RTL8305
14. 最后再加入相机、喊话器等真实业务负载
15. 代码要考虑后续正式产品使用，而不是一次性 Demo

最终目标：

> **先证明 ESP32-S3 + W5500 是可靠的以太网通信底座，再在这个底座上继续开发 SBUS、PWM、GPIO、相机、喊话器和其他业务功能。**
